# 頃合商店 Public API

公開APIの仕様と利用ガイドです。**現在は開発中で、利用開始前の草案です。**
契約の正本は [openapi.yaml](openapi.yaml)（JSON表記のYAML）です。

## 認証とモード

同じ予定エンドポイント `https://api.koroai.supply` を使い、`Authorization: Bearer <key>` で認証します。
`kr_test_` がサンドボックス、`kr_live_` が実注文です。ホーム共通の本番用・テスト用のキーを各1本、自動で用意します。
ホームの月間購入上限を設定すると、契約者がWebでキーを確認・更新できます。追加・削除や細かな権限設定はありません。
ホームの購入上限を解除すると、キーの表示・更新とAPIの利用を停止します。
住所・カード・購入上限の変更、入会、管理操作はこのAPIから行えません。

本番キーはホームの月間購入予算と超過時の動作に従って即時に注文します。注文の受付は決済・配送の完了を意味しません。
サンドボックスは検証用の注文記録を作り、実注文・決済・在庫の引当を行いません。モードを本文やqueryで上書きできません。
キーは暗号化して保存し、購入上限の設定後に再表示できます。更新すると古いキーはすぐ無効になります。
キーは秘密として管理し、会話・ログ・ソースコードへ貼り付けないでください。

## 注文の例

```sh
curl https://api.koroai.supply/v1/orders \
  -H "Authorization: Bearer $KOROAI_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: refill-0001" \
  -d '{"jan":"4901234567894","qty":1}'
```

JANは文字列で、JAN-8/13とチェックディジットを検証します。例のJANは説明用で、取扱商品を保証しません。
`qty` はパッケージ数で、1〜10。金額は税込の日本円です。リクエスト単位の `max_price` はありません。
未取扱商品は注文できず、取り扱いリクエストへ進みます。

## 再送と購入上限

`Idempotency-Key` は任意です。キー・操作ごとに保存し、同じ内容なら同じ結果を返し、異なる内容は409にします。
注文は同じキー・JANの短時間の入力も1件へまとめます。数量の違う入力をその窓内で重ねた場合は409とし、意図せず数量を増やしません。
タイムアウトは注文の失敗を意味しません。同じ冪等キーで再照会し、注文一覧でも結果を確認してください。
任意の新しいキーを生成して自動で注文し直さないでください。
月の境界は日本時間。Web・アプリと同じホームの月間購入予算を使い、並行送信もホーム単位で照合します。
テスト用は予算を確認しますが、実注文の使用額には加算しません。

## 応答と状況確認

成功は `{"data": ...}`、一覧は `{"data": [...], "next_cursor": null}`。
1ページ最大50件で、続きは `cursor` に `next_cursor` を指定します。
注文と取り扱いリクエストは、認可されたホームかつキーと同じモードの記録を照会できます。
キーを更新しても、同じホーム・モードの注文履歴と再送の照合は引き継ぎます。見積もりの照会と注文の取消は、そのキーで作成した記録に限ります。
注文は請求・手配・配送の状態を分けて返し、住所・カード・連絡先・内部のエラー本文を返しません。
取り扱いリクエストは調査中から照会でき、調査・運営の承認は購入の承認を意味しません。

エラーは `{"error":"固定コード"}`。`not_found` は無効なキーと参照できない対象で共通です。
429では `Retry-After` 秒だけ待ちます。リクエスト本文は16KiBまで、未定義項目・重複query・qとjanの同時指定は拒否します。
すべての応答は `Cache-Control: no-store` です。
